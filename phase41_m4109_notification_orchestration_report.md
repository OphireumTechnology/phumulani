### 1. NOTIFICATION ORCHESTRATION OBJECTIVE

Notification orchestration connects authoritative business events to user-facing in-app notifications without violating privacy, creating phantom notifications, or bypassing role authorization. In accordance with Section 9 and 10 of the Master Execution Directive, notifications are strictly consequences of business records and never modify underlying business state.

---

### 2. NOTIFICATION LIFECYCLE & STATE MACHINE

Every notification generated by the platform transitions through strict lifecycle states:

```
[Business Event Committed]
            ↓
       (CREATED)
            ↓
        (READY) ──[Authorization & Preference Check]
            ↓
   (DELIVERED_IN_APP) ──[Recipient Reads Notice]
            ↓
         (READ)
            ↓
       (ARCHIVED)
```

- `CREATED`: Notification record instantiated with event metadata and translation keys.
- `READY`: Recipient resolved against acting session, constituent ownership, and staff queues.
- `DELIVERED_IN_APP`: Committed to `operational_notifications` table in persistent adapter.
- `READ`: Marked read only upon explicit recipient action (`readAt` populated).
- `ARCHIVED`: Retained in audit history but hidden from active dashboard queues.
- `FAILED`: Recipient resolution failure or invalid schema (fails closed).

**External Delivery Staging Rule:**
Because live Google Workspace (Gmail) and commercial SMS gateways remain unauthorized in development (`GOOGLE_WORKSPACE=AUTHORIZATION_REQUIRED`), external delivery status is strictly marked `STAGED` or `BLOCKED_UNAUTHORIZED`. No fake transmission receipts are fabricated.

### 3. TYPED NOTIFICATION CONTRACT

```typescript
export interface ScopedInAppNotification {
  id: string;                               // Unique database primary key
  notificationId: string;                   // Canonical notification identifier
  eventId: string;                          // Originating business event ID
  recipientId: string;                      // Specific constituent ID or queue token
  recipientRole: string;                    // Authorized role family
  notificationType: BusinessEventType;      // Event catalog classification
  category: 'MEMBER' | 'CASEWORKER' | 'PROGRAM' | 'VOLUNTEER' | 'DONOR' | 'REPORTING' | 'GOVERNANCE' | 'SECURITY';
  titleKey: string;                         // Localized translation title key
  messageKey: string;                       // Localized translation message key
  interpolationParams?: Record<string, string | number>; // Safe non-PII parameters
  relatedEntityType: AggregateType;         // Entity type for navigation linking
  relatedEntityId: string;                  // Entity identifier for authorized deep-linking
  createdAt: string;                        // ISO creation timestamp
  readAt?: string;                          // ISO timestamp of explicit read action
  deliveryStatus: NotificationDeliveryStatus; // CREATED | READY | DELIVERED_IN_APP | READ | ARCHIVED | FAILED
  confidentialityLevel: EventClassification;  // PUBLIC | MEMBER_PRIVATE | etc.
  externalDeliveryStatus: 'BLOCKED_UNAUTHORIZED' | 'STAGED' | 'NOT_CONFIGURED';
}
```

### 4. COMMUNICATION PREFERENCES & MANDATORY OPERATIONAL INVARIANT

Constituents and staff can configure communication preferences via `NotificationCenterModal` and `operationalEventService.updateNotificationPreferences()`. However, the following invariant is strictly enforced:

> **OPTIONAL COMMUNICATION PREFERENCES MUST NEVER SUPPRESS MANDATORY OPERATIONAL OR SECURITY NOTICES.**

The following event types are classified as immune to preference suppression:
1. `SERVICE_REQUEST_SUBMITTED`, `SERVICE_REQUEST_ASSIGNED`, `SERVICE_REQUEST_IN_PROGRESS`, `SERVICE_REQUEST_RESOLVED`, `SERVICE_REQUEST_CLOSED`
2. `VOLUNTEER_CLEARANCE_REVOKED`, `VOLUNTEER_SHIFT_CANCELLED`
3. `SECURITY_POLICY_VIOLATION`, `AI_EMERGENCY_HALT_ACTIVATED`

Optional categories subject to constituent choice include:
- `programUpdates`: Workshop reminders and open enrollment notices.
- `volunteerUpdates`: General volunteer newsletters and new shift solicitations.
- `fundraisingCommunications`: Donor stewardship letters and capital campaign appeals.
- `generalAnnouncements`: Holiday schedules and organizational announcements.
