## 1. Governance Purpose & Threat Model

Official operational, financial, and board reports cannot exist purely as transient, in-memory database queries. Any discrepancy between what leadership reviewed and what was subsequently filed with funders or auditors represents a major compliance liability.

Phumulani implements an **Immutable Report Snapshot Engine**:
1. Every official report snapshot captures the exact dataset at a specific millisecond.
2. An SHA-256 cryptographic digest is calculated over the serialized payload.
3. Snapshots cannot be approved by their creator (Separation of Duties).
4. AI agents are strictly barred from approving snapshots.

---

## 2. Snapshot Lifecycle & State Machine

```
[ DRAFT CREATION ]
       │
       ▼  (SHA-256 Checksum Computed & Staged in Durable Store)
[ PENDING_APPROVAL ] ──(Rejection by Reviewer)──► [ REJECTED ] (With Mandatory Reason)
       │
       ▼  (Human Separation-of-Duties Approval)
[ APPROVED ] ──► (Immutable / Sealed for Audits & Funder Filing)
```

### State Machine Definitions:
- `PENDING_APPROVAL`: The snapshot has been generated by a staff member or administrator and placed in the governance review queue.
- `APPROVED`: The snapshot has been reviewed, cross-referenced, and formally approved by a second, independent authorized human reviewer.
- `REJECTED`: The snapshot has been rejected due to data variances, unallowable cost inclusions, or formatting defects, with documented feedback.

---

## 3. Cryptographic Checksum Architecture

The snapshot checksum is computed using Node.js `crypto` with `createHash('sha256')`:

```typescript
const payloadString = JSON.stringify(data);
const checksum = crypto.createHash('sha256').update(payloadString).digest('hex');
```

When an approved snapshot is retrieved or exported, its payload is re-hashed. Any variance between the recomputed hash and the stored `checksum` results in immediate quarantine and audit alert dispatch.

## 4. Separation of Duties Enforcement Protocol

```
+----------------------------------------------------------------------------------------------------+
|                                    SEPARATION-OF-DUTIES ACCESS GATES                               |
+--------------------------+-----------------------+-------------------------+-----------------------+
| Report Category          | Creator Role Allowed  | Approver Role Required  | Self-Approval Allowed |
+--------------------------+-----------------------+-------------------------+-----------------------+
| STAFF_OPERATIONAL        | Staff, Coordinator    | Executive Director, ED  | STRICTLY FORBIDDEN    |
| EXECUTIVE_DASHBOARD      | Executive Director    | Board President / Chair | STRICTLY FORBIDDEN    |
| BOARD_GOVERNANCE         | Executive Director    | Board Secretary / Treas | STRICTLY FORBIDDEN    |
| FUNDRAISING_PERFORMANCE  | Development Director  | Finance Director, ED    | STRICTLY FORBIDDEN    |
+--------------------------+-----------------------+-------------------------+-----------------------+
```

Violation of this protocol (e.g. attempting to self-approve or allow an AI agent to approve) throws an immediate security error and writes an incident record to the security log.
