### 2. Live Email-to-CRM Integration Workflow (M20.09)

When correspondence is ingested, the Email Manager links the message to the corresponding domain in the CRM without polluting audited financial records:

1. **Contact Resolution:** Searches `fundraising_donors` by email address.
   - If found: Links thread to existing donor profile and updates `lastContactDate`.
   - If not found: Stages a prospective contact record for human review.
2. **Opportunity Association:** Links thread to active pipeline deals (`MajorDonorPipelineDeal`, `GrantPipelineOpportunity`, or `CorporatePartnershipOpportunity`).
3. **Financial Truth Invariant:** Email mentions of gifts, grants, or checks (e.g., *"We mailed a $10,000 check"*) are recorded as **tentative notes only**. Under no circumstances does the CRM automatically mark a donation as received or increment audited revenue without certified bank reconciliation.
4. **Confidentiality Partitioning:** Correspondence linked to executive or crisis inboxes is barred from appearing in general CRM activity timelines.

### 3. Fail-Closed Quad-Action Human Approval Engine (M20.10)

The platform enforces a non-negotiable **human-in-the-loop** approval barrier for all outbound communications generated by AI agents or staff:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        QUAD-ACTION APPROVAL WORKFLOW                   │
├───────────────────┬────────────────────────────────────────────────────┤
│ Action            │ Effect & System State Transition                   │
├───────────────────┼────────────────────────────────────────────────────┤
│ 1. APPROVE        │ Verifies content hash (SHA-256), signs approver    │
│                   │ name & timestamp, transitions status to APPROVED.  │
├───────────────────┼────────────────────────────────────────────────────┤
│ 2. REQUEST_CHANGES│ Flags specific editorial feedback to drafter;      │
│                   │ remains locked in pending review state.            │
├───────────────────┼────────────────────────────────────────────────────┤
│ 3. RETURN_TO_DRAFT│ Revokes pending approval status; unlocks draft for │
│                   │ revisions; invalidates previous hash.              │
├───────────────────┼────────────────────────────────────────────────────┤
│ 4. REJECT         │ Terminates outreach task; archives draft with      │
│                   │ documented policy/safeguarding rationale.          │
└───────────────────┴────────────────────────────────────────────────────┘
```

#### Tamper-Proofing Rules:
- If an approved draft is modified by even one character, the cryptographic signature (`contentHash`) becomes invalid, and the draft immediately reverts to `pending_approval`.
- No AI agent has the programmatic privilege to call the dispatch endpoint directly.

### 4. Controlled Outbound Dispatch Verification (M20.11)

Outbound dispatch (`/api/fundraising/dispatch` and `/api/email/dispatch`) is protected by strict controls:

- **Emergency Shutdown Gate:** If `emergencyShutdownActive` is toggled by security or leadership, all outbound network dispatch terminates immediately with HTTP 503.
- **Anti-Duplication:** Each task records `dispatched: true` and `dispatchedAt`. Secondary attempts return HTTP 409 Conflict.
- **CAN-SPAM Compliance:** Agent `FUND-AI-009` checks suppression lists and ensures physical postal address (`PO Box, Minneapolis, MN 55404`) and one-click unsubscribe headers are embedded.

### 5. Background Worker Durability & Recovery (M20.12)

The `BackgroundWorkerService` manages asynchronous tasks (mailbox sync, import batches, report generation):
- **Durable Job Leases:** Tasks are locked to an active worker for 5 minutes.
- **Interruption Recovery:** On application startup, `recoverStaleLeases()` queries expired leases and resets them to `PENDING` with an incremented `retryCount`.
- **Dead-Letter State:** After 3 consecutive failures, tasks transition to `DEAD_LETTER` and alert administrators in the audit log.
